**狀態：** 設計定稿，待寫實作計畫
**日期：** 2026-10-06
**前置：** 介面改版第一階段（規格 `2026-10-02-ui-redesign-phase1-design.md`）、AI 估算的前端已合併（master `a6672ec`）

## 1. 目標與範圍

### 1.1 為什麼要做

第一階段換了總覽、記帳、記一餐、飲食頁的外觀，但**六個畫面還是瀏覽器預設樣式**：食物庫、食物詳情、
新增食物、補劑、趨勢、管理員審核——沒有樣式檔，按鈕不到 44px，`index.css` 裡還有寫死的舊顏色
（`#4a7`、`#c33`、`#eee`、`#777`、`#2a6`、`#b33`），深色模式下對比不夠。使用者說過「前端很醜」，
而新增食物、食物庫是最近每天在用的畫面。

報表的分類佔比是一列列文字，看不出「整體的一半」這種比例感；趨勢圖只有熱量。

### 1.2 這份規格做的事

1. 六個舊畫面（加上新增份量表單）**只換外觀**：卡片、統一的輸入框與按鈕、44px。
2. `index.css` 清掉寫死的舊顏色，全部換成設計變數。
3. 報表頁的分類佔比改成**甜甜圈圖＋清單**。
4. 趨勢頁加**營養素切換**（熱量／蛋白質／脂肪／碳水），換新外觀。

### 1.3 明確不做

- **重新排版**（收合區塊、改順序、改標籤）——使用者選了「只換外觀」（§2）。
- 已經換過外觀的畫面（總覽、記帳、記一餐、編輯這一餐、飲食頁、我的）不動。
- 趨勢的期間切換（30 天）、摘要數字（本週平均、達標天數）。
- 記住趨勢上次選的營養素。
- 第三階段社群（P7）。

## 3. 舊畫面換外觀

### 3.1 範圍

| 畫面 | 檔案 |
|---|---|
| 食物庫 | `frontend/src/screens/FoodLibrary.tsx` |
| 食物詳情 | `frontend/src/screens/FoodDetail.tsx`（含 `components/AddPortionForm.tsx`） |
| 新增食物 | `frontend/src/screens/NewFood.tsx` |
| 補劑 | `frontend/src/screens/Supplements.tsx` |
| 趨勢 | `frontend/src/screens/Trend.tsx`（外觀；圖表見 §5） |
| 管理員審核 | `frontend/src/screens/AdminRevisions.tsx` |

每個畫面一個自己的 `*.module.css`。

### 3.2 共用的樣式積木

新增 `frontend/src/components/ui.module.css`，放六個畫面共用的：

- 區塊卡片（`.section`）與區塊標題（小一號的灰字，跟總覽一致）
- 欄位（`.field`：標籤在上、輸入框在下）、輸入框與下拉（`.input`）
- 按鈕：主要（`.primary`）、次要（`.secondary`）、危險（`.danger`）——都至少 44px
- 狀態標籤（`.tag`：小圓角，用在「預設」「已通過」「待審」「已駁回」「公開」）
- 提示文字（`.hint`）、錯誤（`.error`）

已經換過外觀的畫面**不改用它**——不為了統一去動已經能用的東西。

### 3.3 每個畫面的做法

- 每一區包進一張卡片。
- 營養素數字改成 2×2 小方格（熱量、蛋白質、脂肪、碳水）。
- 狀態改成小圓角標籤。
- 所有按鈕與可點的列至少 44px。
- **標籤文字、元素順序、按鈕名稱、`data-testid`、`id` 一律不變。**
  既有的單元測試與 e2e **一條都不改**、全部照樣綠——那就是證明。

### 3.4 `index.css` 的舊顏色

`index.css` 裡食物清單（`.food-results`、`.food-brand`、`.food-tag`、`.food-no-nutrition`）與趨勢圖
（`.trend-bar`、`.trend-target`）用的色碼，全部換成設計變數：

- 需要新的語意色就加變數（例如「公開」標籤的綠色 `--color-success`），淺色與深色模式各一組。
- 新變數在兩種模式下對文字底色的對比都 ≥ 4.5:1（沿用既有的對比度測試）。
- 換完之後，**`index.css` 除了設計變數的定義之外不再有任何色碼**——加一條測試守著。

## 4. 報表：甜甜圈圖＋清單

### 4.1 `CategoryDonut`（新元件）

- SVG 甜甜圈，中間寫「總計」與金額（`formatMoney`）。
- 每個分類一段弧，顏色用既有的 `CATEGORY_COLORS`，順序跟清單一樣（`by_category` 的順序）。
- **弧的長度與起點算成 SVG 屬性**（`stroke-dasharray`／`stroke-dashoffset`），不交給 CSS——jsdom
  不做版面計算，交給 CSS 的話「弧長比例等於金額比例」就測不到（同 `TrendChart` 的作法）。
- 佔比用 `ratioOf()`（`lib/decimal.ts`），不做浮點除法。
- 只有一個分類 → 整圈。
- **圖本身是裝飾**（`aria-hidden`）：清單已經有全部的數字，螢幕閱讀器不需要再唸一次。

### 4.2 清單

沿用 `CategoryBar`（每個分類一列），加色點、換新外觀。內容不變：分類名、金額、筆數、百分比；
`data-testid="category-{分類}"` 保留。

### 4.3 空狀態

這個月沒有支出（`by_category` 是空的，或總計是 0）→ 不畫圖，寫「這個月還沒有支出」。

## 5. 趨勢：營養素切換

### 5.1 切換

- 上方一組單選按鈕（`radiogroup`）：熱量、蛋白質、脂肪、碳水。預設熱量。每次進來都是熱量（不記住）。
- 鍵盤可操作（方向鍵在選項間移動是 radio 的原生行為）。

### 5.2 `TrendChart`

- 多一個參數：要畫哪一項（`"kcal" | "protein_g" | "fat_g" | "carb_g"`），預設 `"kcal"`。
- 長條、目標線、單位（kcal 或 g）跟著那一項。
- 那一項沒有目標 → 不畫目標線。**兩層 null 的語意不變**（`target` 是 null＝那天沒有生效目標；
  `target.{項}` 是 null＝有目標但這一項沒設）。
- 今天那一根（陣列最後一天）用淡色——今天還沒結束。
- 圖下面一行：「今天 1,240 / 2,000 kcal」；沒有目標時只寫「今天 1,240 kcal」。
- 外觀：卡片、圓角柱子、虛線目標線，顏色全用設計變數。
- 幾何照舊算成 SVG 屬性（高度、y）。

### 5.3 其他

補劑依從率包成一張卡片，文字與 `data-testid="adherence"` 不變。

## 6. 測試

### 6.1 舊畫面

- 既有的單元測試與 e2e **一條都不改**、全部綠。
- `index.css` 除了變數定義之外沒有色碼（新測試）。
- 新變數的對比度（擴充既有的 `css-tokens.test.ts`）。
- e2e：手機尺寸下，六個畫面上的按鈕高度都 ≥ 44px（新的 spec，量 `getBoundingClientRect`——Playwright
  的瀏覽器有版面計算，jsdom 沒有）。

### 6.2 甜甜圈圖

- 弧長比例等於金額比例——用兩組不同的金額驗證（只用一組的話，寫死比例的實作也會綠）。
- 只有一個分類 → 整圈。
- 沒有支出 → 不畫圖，「這個月還沒有支出」。
- 中間的總計、清單的百分比。

### 6.3 趨勢切換

- 切到蛋白質：柱子高度、目標線、單位都換成蛋白質的。
- 某一項沒有目標 → 不畫目標線（另一項有目標時照畫——證明是「那一項」的 null，不是整天）。
- 今天那根是淡色。
- 突變：把「畫哪一項」寫死成熱量 → 紅。
- 既有的 `trend-chart.test.tsx`、`trend.test.tsx` 照樣綠（預設熱量）。
