## 1. 目標與範圍

### 1.1 為什麼要做

四件每天用得到、但一直被延後的小事（交接文件 §8.2、介面改版的已知待辦）：

1. **份量加錯就改不掉**——後端只有新增與列出份量，沒有修改、刪除（食物份量規格 §1.3 明寫「不做」）。
2. **食物詳情的編輯歷史日期是原始字串**（`2026-10-06T07:32:01.552755Z`）。
3. **趨勢圖沒有日期軸**——每根柱子是哪一天只在 aria-label 裡。
4. **報表頁支出清單的「修改」「刪除」**還是瀏覽器預設的小按鈕（報表是第一階段的畫面，第二階段刻意沒動）。

### 1.2 明確不做

- 社群（P7）——下一個大項目，前置是「開帳號的路」。
- 管理員在介面上建立或管理公開份量（公開份量的修改、刪除只開放 API 給管理員）。
- 趨勢圖的期間切換、摘要數字。
- 報表頁其他部分換外觀。

## 3. 份量的修改與刪除

### 3.1 後端

**`PATCH /api/foods/{food_id}/portions/{portion_id}`**

- 請求：`{ label?, grams?, is_default? }`，`exclude_unset`（不帶＝不動）。限制同 `PortionCreateRequest`
  （`label` 1–50 字、`grams` `gt=0, le=10000, max_digits=8, decimal_places=2`）；顯式 `null` → 422
  （三個欄位都是 NOT NULL）。
- `is_default: true` → 同一個交易裡取消**同一個擁有者、同一個食物**的其他預設（同 `create_portion`）。
- 改名撞到同名（`uq_food_portions_food_id_owner_id_label`）→ `409 PORTION_EXISTS`（訊息同新增）。
- 回應：`PortionResponse`。

**`DELETE /api/foods/{food_id}/portions/{portion_id}`** → 204。`meal_items.portion_id` 由資料庫 `SET NULL`。

**誰能動哪個份量：**

| 份量 | 一般使用者 | 管理員 |
|---|---|---|
| 自己的私人份量 | 可以 | 可以（自己的） |
| 公開份量（`owner_id IS NULL`） | `403 FORBIDDEN`（同「新增公開份量」的規則：看得到但不能動） | 可以 |
| 別人的私人份量 | `404`（不透露存在，handover §4.7） | `404` |
| 份量不屬於路徑上的食物 | `404` | `404` |

食物本身要看得到（`load_visible_food`），看不到 → 404。

### 3.2 已記的餐不受影響

- 改重量：舊紀錄的 `quantity_g` 不變（寫入時算好）。測試要證明。
- 刪除：舊紀錄的 `portion_id` 變 null、`quantity_g` 不變。測試要證明。

### 3.3 前端（食物詳情的份量清單）

- **只有私人份量能動**（`!portion.is_global`）：每一列多「修改」「刪除」。公開份量的修改、刪除只開放 API 給管理員（§1.2），
  介面上任何人都看不到這兩個按鈕。後端仍然是授權的唯一依據——前端藏按鈕是可用性。
- **修改**：在那一列展開小表單（名稱、重量、「記一餐時預設用這個份量」），只送有改的欄位；「儲存」「放棄」。
  同一時間只開一個。
- **刪除**：確認（`role="alertdialog"`），文字寫明「已經記下的餐不受影響，公克數照舊」。
- 成功 → 失效 `queryKeys.portions(foodId)`（記一餐、編輯畫面用同一個 key）。
- 錯誤：`409 PORTION_EXISTS` → 後端訊息；`422` → 欄位錯誤（`describeFieldErrors`）；其他 → 「儲存失敗，請再試一次」／「刪除失敗，請再試一次」。

## 4. 編輯歷史的日期

- `lib/dates.ts` 新增 `formatDateTime(timestamp)`：`toLocaleString(undefined, { year: "numeric", month: "numeric", day: "numeric", hour: "2-digit", minute: "2-digit" })`。
  只做顯示格式化，不算日界線（符合 `lib/dates.ts` 開頭的規矩）。
- 食物詳情的編輯歷史用它顯示 `created_at`。
- **這是刻意的行為改變**：`tests/food-detail.test.tsx` 有一條斷言原始 ISO 字串（`2026-09-01T00:00:00Z`），
  要改成斷言 `formatDateTime(...)` 的輸出。

## 5. 趨勢圖的日期軸

- 每根柱子下面一個 SVG `<text>`：`formatCivilDate(day.date)`（例如 `9/15`）；`day.date === today` 的那一根寫「今天」。
- 日期放在柱子區域**下面多出來的一條**：`viewBox` 的高度加一段（例如 16），柱子的計算範圍（`VIEW_HEIGHT`）不變——
  既有的高度比例與位置測試照樣成立。
- 文字是裝飾（`aria-hidden`）：每根柱子的 aria-label 已經有日期。

## 7. 測試

### 7.1 後端（份量）

- 改名稱、重量、預設；只送一個欄位時其他不動。
- 改重量之後，用這個份量記過的餐 `quantity_g` 不變。
- 改成預設 → 原本的預設被取消（只動同一個擁有者的）。
- 刪除 → 餐點那一項 `portion_id` 是 null、`quantity_g` 不變。
- 別人的私人份量 → 404；一般使用者改／刪公開份量 → 403；管理員可以。
- 份量不屬於路徑上的食物 → 404。
- 改名撞名 → 409；顯式 null → 422。

### 7.2 前端

- 份量：修改送出的 body 只有改過的欄位；刪除先確認、取消不送；一般使用者在公開份量上沒有按鈕；
  成功後失效份量清單；409 的訊息。
- `formatDateTime` 自己的測試；食物詳情改用它的輸出斷言。
- 趨勢日期軸：每根柱子下有對應的日期；今天那根寫「今天」。
- e2e：報表清單的按鈕 ≥ 44px（`e2e/touch-targets.spec.ts` 加一條；先建一筆支出才有按鈕）。
