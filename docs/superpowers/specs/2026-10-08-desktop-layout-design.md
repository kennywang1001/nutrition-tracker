# 電腦版版面：左側導覽＋多欄的總覽／報表／飲食

**狀態：** 已實作（`feat/desktop-layout`）。設計定稿於 2026-10-08。
**前置：** NAS 改用 CI 映像部署（master `9f3e469`）。
**起因：** 使用者第一次用電腦開 app（`https://kennywang.tailc1f9e9.ts.net`）。目前整個畫面拉滿螢幕寬：卡片橫跨一千多 px、
記帳的數字鍵盤變得巨大、底部分頁列在桌機上很怪。

## 1. 範圍

只改**版面**：同樣的內容、同樣的流程、同樣的網址，在寬螢幕上換一種排法。不加新內容、不碰後端。

- 寬度 **≥ 1024px**：左側導覽＋內容區（總覽、報表、飲食排兩欄）。
- 寬度 **< 1024px**：現在的手機版，**唯一**的差別是內容最寬 600px、置中（直立的平板不再拉滿）。

不做：右側滑出的新增面板（新增流程維持整頁）、總覽加新卡片（例如趨勢圖）、可拖拉的版面、記住使用者偏好的版面。

## 2. 決定

| 項目 | 做法 | 理由 |
|---|---|---|
| 版面程度 | 左側導覽＋總覽／報表／飲食兩欄（使用者選 C） | 電腦上一眼看到更多 |
| 新增流程 | 維持整頁（`/expenses/new`、`/meals/new`），電腦上置中、最寬 480px，左側導覽照常顯示（使用者選 A） | 記一筆只要幾秒；面板要做兩套焦點／Esc／返回鍵行為 |
| 斷點的唯一來源 | `useIsDesktop()`（`matchMedia("(min-width: 1024px)")`，`useSyncExternalStore`），外框依結果畫導覽並加上 `app-desktop` class；頁面的兩欄 CSS 寫成 `:global(.app-desktop) .x { … }` | 1024 只出現在一個地方；jsdom 可以測（CSS media query 在 jsdom 裡不生效） |
| 為什麼導覽不用純 CSS 換位置 | 左側導覽的「新增」在最上面，分頁列的「＋」在中間；只用 CSS `order` 換位置的話，Tab 順序跟畫面不一致 | 鍵盤使用者 |
| 名稱不變 | `SideNav` 的 `<nav aria-label="主要導覽">`、按鈕 `aria-label="新增紀錄"`（看得到的字是「新增」，名稱包含看得到的字）、連結名稱 總覽／報表／飲食／我的 | 現有單元測試與 e2e 的 `getByRole` 照樣找得到 |
| 「新增」選單 | 沿用 `AddSheet`；電腦上是畫面中間、最寬 400px 的對話框，不是從底部滑上來的面板 | 寬螢幕的底部面板會橫跨整個畫面 |
| 開關狀態 | 把 `TabBar` 裡「在哪個 location 打開的」那段邏輯抽成共用 hook，`TabBar` 與 `SideNav` 都用它 | 換頁自動關、返回不會再跳出來——兩邊行為一致 |

## 3. 外框（`App.tsx` 的 `LoggedInShell`）

- **手機版**：跟現在一樣（`/expenses/new` 隱藏分頁列的規則不變）。`.app-main` 加 `max-width: 600px; margin-inline: auto`。
- **電腦版**：外框 `app-desktop`；左邊固定的 `SideNav`（寬 200px、整個高度、`position: fixed`）；`main` 讓出左邊的寬度，
  沒有為分頁列留的底部空白。**每一頁都顯示 `SideNav`**，包括記帳。
- **內容寬度依路由**（外框決定，表格放在一個小模組裡，例如 `lib/layout.ts`）：

| 路由 | 電腦版內容最寬 |
|---|---|
| `/`、`/reports`、`/diet` | 1100px |
| `/expenses/new`、`/meals/new` | 480px |
| 其他（我的、食物庫、食物詳情、新增食物、趨勢、補劑、編輯餐點、好友那一天、審核、`/join`） | 640px |

  內容區在 `SideNav` 右邊的空間裡置中。

- **未登入**：登入頁與建立帳號頁置中、最寬 400px（兩種寬度都一樣）。

## 4. 各頁的兩欄（只在 `app-desktop` 下）

兩欄是 `minmax(0, 2fr) minmax(0, 3fr)`、上緣對齊；一欄比較短沒關係，整頁一起捲，不做各欄獨立捲動。

- **總覽**：左＝本月支出、今天熱量兩張卡（上下疊，不再並排）；右＝「今天」時間線。離線提示與通知在兩欄之上。
- **報表**：「營養趨勢」連結在兩欄之上；左＝「這個月花了多少」摘要；右＝「這個月」明細清單。
- **飲食（我的）**：「看誰的」與「食物庫」連結在兩欄之上；左＝營養素進度、今日補劑；右＝今天的餐點卡片。
  **DOM 順序不變**（營養素 → 餐點 → 補劑），用 `grid-template-areas` 把補劑放到左欄下方、餐點跨兩列——
  不然手機版的順序會跟著變。
- **飲食（好友）**：單欄，最寬 640px，靠左（跟上面的「看誰的」對齊）。

總覽、報表的兩欄用「左一個容器、右一個容器」包現有的區塊——那兩頁本來的順序就是先左後右，手機版不受影響。

## 5. 細節

- 左側導覽的連結：圖示＋文字橫排，可點選區高度 ≥ 44px；目前那一頁 `aria-current="page"`（`NavLink` 自帶）並反白；
  滑鼠移過去有底色（只在電腦版）。
- 「新增」按鈕用珊瑚橘（`--color-action`），跟手機版的「＋」同色。
- 所有新顏色只能用 `index.css` 的變數（`css-tokens.test.ts` 會掃）。
- 數字鍵盤：記帳頁最寬 480px，鍵盤跟著；不另外改鍵盤的樣式。
- 視窗從寬拉到窄（或反過來）時即時切換；`AddSheet` 開著時切換會關掉（導覽元件換了一個）——可接受。

## 6. 測試

**單元（Vitest）**
- `src/test/setup.ts` 裝一個可控制的 `matchMedia` 假實作，**預設不符合**（＝手機版），所以現有測試全部不受影響；
  提供切換寬度的工具函式，切換時通知 `change` 監聽者。
- `useIsDesktop`：初始值、`change` 之後更新、`matchMedia` 不存在時回 `false`。
- 外框：電腦版有「主要導覽」且裡面第一個可聚焦的是「新增紀錄」、沒有底部分頁列的樣式、`main` 外層有 `app-desktop`；
  手機版維持現狀；從電腦版切到手機版會換回分頁列。記帳頁在電腦版**有**導覽。
- `SideNav`：「新增紀錄」打開新增選單、換頁後選單關閉、`aria-current` 正確（`/diet` 時「總覽」不亮）。
- 內容寬度的路由表：每一條路由對到正確的寬度類別（`/expenses/new/` 也算記帳）。
- 飲食頁在電腦版與手機版的 DOM 順序都是 營養素 → 餐點 → 補劑。

**e2e（Playwright）**
- 新的 `e2e/desktop-layout.spec.ts`：
  - 1280×800：「主要導覽」在畫面左側；`/`、`/reports`、`/diet`、`/me`、`/expenses/new` 都沒有橫向捲軸；總覽的時間線在數字卡的右邊；
    記帳的數字鍵盤寬度 ≤ 480px。
  - 390×844：「主要導覽」在畫面底部；同樣幾頁沒有橫向捲軸。
- 現有 e2e 多數跑在 Playwright 預設的 1280×720，等於自動變成電腦版的回歸測試；`touch-targets`、`mobile-form-zoom`、
  `friends`、`invites` 本來就固定手機尺寸，繼續守手機版。

## 7. 交付

一個前端分支：外框／`useIsDesktop`／`SideNav` 一個任務，三頁的兩欄一個任務，e2e 與交接文件一個任務。不碰後端、不動 API。

## 8. 實作時追加：三個沒改版過的畫面

介面改版的兩個階段漏掉了三個地方，在電腦版的寬畫面上特別明顯，這個分支一起補（只改樣式與標記，行為、可及名稱、testid 不變）：

- **登入**（`Login.tsx`）：原本是一行裸表單。改成跟建立帳號同一套 `ui.module.css` `.screen`：卡片、標籤在上的輸入框、整列主要按鈕；
  `.app-auth` 加上隨視窗高度的上方內距（`clamp(var(--space-6), 10vh, 120px)`，不寫 media query）；標題上緣離視窗頂端再加 h1 自己的
  `margin-top: var(--space-3)`（`:where(.screen h1)`），實際是 clamp＋12px。建立帳號頁（`/join`）也在 `.app-auth` 裡，一起往下移。
- **飲食頁營養素**（`MacroBar.tsx`、`Today.tsx`）：每列名稱在左、數字與百分比在右，下面一條跟總覽「今天熱量」相同的進度條
  （`ratioOf()`、`Math.min(ratio, 1)`）；「未設定」不畫條。沒有目標時的 `<dl>` 排成名稱左、數值右的列。
- **今日餐點卡片**（`MealList.tsx`）：上傳照片照編輯這一餐的「加照片」改成虛線框按鈕（input 藏起來仍可對焦，名稱仍是「上傳照片」）；
  項目去掉項目符號、份量灰色；合計靠右；縮圖最寬 240px。「今日餐點」「今日補劑」標題改成小字灰色的區塊標題。
