# AI 與編輯畫面的收尾

**狀態：** 已實作（1～8 項都完成，2026-10-08；使用者授權「剩下的待辦用推薦的做法做完」）
**前置：** 記帳畫面與離線已合併（master `36463c7`）

## 1. 範圍（handover §8.2 的 AI 已知限制、編輯畫面的已知缺口）

**AI**
1. 「編輯這一餐」的加一項沒有 AI——`FoodPicker` 的 `renderBelowSearch` 沒給。
2. 供應商的 SDK 丟錯（金鑰、`AI_MODEL` 錯）時端點回 500、畫面說「AI 估算失敗」，而且**算一次額度**。
3. AI 確認存出的私人食物可能跟看得到的食物同名——之後文字估算命中食物庫時優先回自己那一筆。
4. 面板在「結果卡片 ↔ 修改表單」切換時沒有移動焦點。
5. `analyzeImage` 與 `uploadMealPhoto` 重複「擋大小＋縮到 1280」。

**編輯畫面**
6. `useMeal`／`useFood` 遇到 404 仍重試 3 次（約 7 秒才顯示「找不到這一餐」）。
7. 從清單點進來仍先看到「載入中」（可以用清單快取當 `placeholderData`）。
8. 確認框（刪這一餐、刪照片、刪一項）沒有移動焦點。

**不做（記進交接文件）：** 一次估算多樣食物、估算用的照片另外存、額度的並行競爭、`ai_raw_response` 來源、
「改項目後要等五個 query 重抓完編輯器才收起」。

## 2. 決定（推薦的做法）

| 項目 | 做法 |
|---|---|
| 1 | 編輯畫面的 `FoodPicker` 給 `renderBelowSearch`，同記一餐用 `AiEstimatePanel`；存好的食物交回「加一項」的選擇（份量一份 × 1）。照片不帶（這一餐的照片由照片區處理） |
| 2 | 兩個 estimator 把 SDK 的例外分兩類：**設定錯誤**（認證、權限、找不到模型）→ `503 AI_MISCONFIGURED`「AI 設定有問題（金鑰或模型），請管理員檢查」，**不記一列、不算額度**（供應商直接拒絕，沒有計費）；**上游錯誤**（連線、逾時、5xx、限流）→ `502 AI_UPSTREAM_ERROR`「AI 服務暫時無法使用，請稍後再試」，照舊記一列（可能已經計費——規格 §7「兩種都花了錢」）。`AI_BAD_RESPONSE` 不變。前端面板依 code 顯示後端訊息 |
| 3 | 確認存出之前，用估算的名稱搜一次看得到的食物（`GET /api/foods?q=`）；有**名稱完全相同**（去頭尾空白、不分大小寫）的就先問：「食物庫裡已經有「X」」＋「用食物庫的」／「還是用 AI 的數字建一個」 |
| 4 | 切到修改表單 → 焦點到第一個欄位；切回結果卡片 → 焦點到卡片的標題（`tabIndex={-1}`） |
| 5 | 抽成 `lib/photo.ts` 的 `preparePhoto(file)`（擋大小＋縮到 1280），兩邊共用；行為不變 |
| 6 | `retry`：`ApiError` 404 不重試，其他照舊（最多 3 次） |
| 7 | `useMeal` 的 `placeholderData`：今天的餐點清單快取裡找到同一個 id 就先用它 |
| 8 | 確認框打開時焦點到「取消」（安全的那一顆）；取消後回到原本的按鈕 |

## 3. 測試

每一項先紅後綠；後端：設定錯誤 503 不記列、上游錯誤 502 記一列（兩個 estimator 各一組，用假的 SDK 例外）；
前端：編輯畫面有 AI 面板且存好的食物進到加一項、同名提醒的兩個按鈕、焦點、`preparePhoto` 的大小與縮圖、
404 只打一次、從清單快取先顯示、確認框焦點。
