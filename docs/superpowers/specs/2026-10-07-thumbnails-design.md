# 照片縮圖與看大圖

**狀態：** 已實作
**日期：** 2026-10-07
**前置：** 上線前的安全補強已合併（master `23dc4f3`）

---

## 1. 目標與範圍

### 1.1 為什麼要做

照片上傳時縮成長邊 1280px 的 JPEG，**只有這一份**——飲食頁的餐點卡片、好友動態、編輯這一餐的預覽
都抓它。好友動態一次十幾張，全是 1280px（handover §8.2「清單頁載入多張 1280px 圖會慢」）。

### 1.2 這份規格做的事

1. 上傳時同時存一份縮圖（長邊 640）；舊照片第一次被要縮圖時補做。
2. 照片端點多一個 `?size=thumb`。
3. 清單（飲食頁、好友動態、好友的某一天）用縮圖；點照片全螢幕看原圖。

### 1.3 明確不做

- 多種尺寸、`srcset`。
- HTTP 快取標頭（換照片後網址不變，加了會看到舊圖）。
- 手勢縮放、左右滑看下一張。
- 編輯這一餐的預覽改成縮圖（那裡照舊原圖、不放大）。

## 2. 已經做出的決定

| 決定 | 選項 | 理由 |
|---|---|---|
| 縮圖用在哪 | **清單一律縮圖、點了看大圖**（使用者選 A） | 清單快、細節還看得到（好友的照片也是） |
| 怎麼產生 | **上傳時存一份；舊照片第一次被要時補做**（A） | 只縮一次；不用改資料庫（檔名推得出來）、不用另外跑補做指令 |

## 3. 後端

### 3.1 存檔（`app/storage/photos.py`）

- `THUMBNAIL_DIMENSION = 640`、`THUMBNAIL_QUALITY = 80`。
- `thumbnail_path(rel_path) -> str`：`"7/ab12….jpg"` → `"7/ab12…_thumb.jpg"`。**全系統唯一一份規則**。
- `save_photo` 存原圖之後，用**同一張已縮到 1280、已去 EXIF 的圖**再縮到 640 存縮圖。回傳值不變（原圖的相對路徑）。
- `read_thumbnail(rel_path) -> bytes`：
  - 縮圖存在 → 讀它。
  - 不存在（這個功能之前上傳的）→ 讀原圖、縮、存、回傳。
  - 原圖也不在 → `FileNotFoundError`（呼叫端照現在轉 404）。
- `delete_photo` 一起刪縮圖（同樣 best-effort：刪不掉記 log，不讓請求失敗）。

### 3.2 端點

`GET /api/meals/{id}/photo` 與 `GET /api/friends/{fid}/meals/{mid}/photo` 多一個查詢參數
`size: Literal["full", "thumb"] = "full"`（其他值 → 422）。授權一字不改，只是選哪個檔案。

`read_thumbnail` 可能要縮圖（Pillow、CPU），用 `run_in_threadpool` 呼叫（同 Argon2 的理由）。

### 3.3 清孤兒照片的指令（`app/cli.py`）

**這一定要改**：它把資料庫沒提到的檔案全部當孤兒——縮圖會被刪光。被引用的集合要加上每個原圖的
`thumbnail_path`；孤兒原圖的縮圖本來就不在集合裡，照常被刪。

## 4. 前端

### 4.1 取圖（`api/photos.ts`）

- `useMealPhoto(mealId, size = "full")`、`useFriendMealPhoto(friendId, mealId, size = "full")`。
- 原圖：路徑與 query key 跟現在一樣。縮圖：路徑加 `?size=thumb`、key 多一段 `"thumb"`
  （`["meal-photo", id, "thumb"]`、`["friend-photo", fid, mid, "thumb"]`）——上傳／刪照片時既有的
  「失效這一餐的照片」是前綴比對，兩個一起失效；解除好友時 `friendPhotos(fid)` 也一起移除。
  兩者照舊不持久化。

### 4.2 `PhotoViewer`（新元件）

- 清單的照片是一個按鈕，裡面是縮圖；按鈕名稱「看大圖：{原本的 alt}」。
- 按下去打開全螢幕深色遮罩（`role="dialog"`、`aria-modal="true"`、`aria-label` 同 alt），**這時才抓原圖**；
  抓的時候先顯示縮圖。
- 關閉：右上角「關閉」、點遮罩（不是點圖）、Esc。打開時焦點移到「關閉」；關掉時回到原本的照片按鈕。
- 用在：飲食頁的餐點卡片（`MealList.tsx`）、好友的餐點卡片（`FriendMealCard.tsx`，動態與某一天都用它）。
- 大圖用 portal 掛到 `document.body`（卡片的祖先可能建立疊放範圍，留在原地會被底部分頁列蓋住）；
  遮罩用 `--viewer-scrim`（90% 黑）。

## 5. 測試

### 5.1 後端

- 上傳之後原圖與縮圖都在；縮圖長邊 640（原圖比 640 小時不放大）、沒有 EXIF。
- 舊照片（只有原圖）：第一次 `read_thumbnail` 補做並存檔；第二次直接讀（spy 縮圖函式只被呼叫一次）。
- `delete_photo`、換照片之後舊縮圖也不見。
- 清孤兒指令：被引用原圖的縮圖**不刪**；孤兒原圖與它的縮圖**都刪**。
- 兩個端點的 `size=thumb`：回的是縮圖（尺寸比原圖小）；非擁有者、非好友、私人的餐 → 404（授權不變）；
  `size=huge` → 422。

### 5.2 前端

- 卡片要的是 `?size=thumb`，**沒有**抓原圖；點了才抓原圖。
- 「關閉」、Esc、點遮罩都能關；點圖本身不關。焦點：打開到「關閉」、關掉回照片按鈕。
- 好友卡片用好友的縮圖端點。
- 編輯這一餐的預覽照舊抓原圖。
- e2e：既有的照片與好友 e2e 照樣綠（好友 e2e 斷言卡片裡的 `img` 有載入——現在是縮圖，應照樣成立）。
